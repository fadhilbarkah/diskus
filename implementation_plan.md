# Fix Email Privacy Leak in Avatars

The current implementation has a privacy leak where user email addresses are exposed in two places:
1. In the `src` URL of the Dicebear avatar images (both in the widget and dashboard).
2. In the raw JSON response of the `GET /api/v1/widget/comments` API, which is publicly accessible.

## Proposed Changes

### Backend (`/backend/src/controllers/widget.controller.ts`)
- Modify `getComments` to strip the `authorEmail` field before returning comments to the client.
- Add an `avatarSeed` property to each comment, generated by hashing the `authorEmail` securely on the server (using SHA-256).

### Widget (`/widget/src/components/CommentThread.tsx` & `CommentForm.tsx`)
- Update the avatar `img src` to use the `avatarSeed` provided by the backend (for existing comments) or a locally hashed version of the email (for the comment form preview).
- Update the permission check for showing the "Delete" menu. Instead of checking `widgetUser.value.email === comment.authorEmail`, we will hash the local user's email and compare it against `comment.avatarSeed`.

### Dashboard (`/dashboard/src/pages/Settings.tsx`)
- Hash the user's email before appending it to the Dicebear URL to prevent the raw email from leaking in network requests.

## User Review Required

> [!WARNING]
> This change will modify the public API response for `GET /comments` by removing `authorEmail` and adding `avatarSeed`. If you have any other frontend clients relying on `authorEmail`, they will need to be updated. Are you okay with this?
